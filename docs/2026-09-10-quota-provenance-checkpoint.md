### E4 versus criterion 7: logical origin is not visual column zero

The original E4 and criterion 7 conflict if “row start” means merely the start of any rendered row. Resolve it by making the term precise:

- A **logical VT row** is a retained row beginning independently of a soft-wrap continuation in the renderer's current state. It is not a claim about authorship or an immutable original stdout line. Cursor-addressed repainting can change that state.
- For notice extraction only, retain raw-row wrap metadata and join soft-wrapped continuations to their known leading row before whitespace normalization. `RowIteration::raw_row()` exists in `vendor/libghostty-rs/crates/libghostty-vt/src/render.rs:539`; `Row::is_wrapped` and `is_wrap_continuation` exist in `screen.rs:105-110`. No new VT parser or vendor rewrite is needed. A continuation whose origin is outside the retained viewport/window cannot independently become an anchor.
- The measured `⎿` / `■` must lead that logical row modulo indentation. A prefix such as `(Fable): `, `Earlier provider result: `, a tool container, or a JSON key disqualifies it even if resize/soft wrap places the quoted glyph at column zero on the next physical row. This is what the padded JSON draft tests.
- Preserve the measured CLI's explicit hard-line wrapping too: AnyLineWrapped may join the anchored first logical row to its next measured continuation. The anchor must belong to the first row; no arbitrary preceding row may borrow an anchor from the second. Keep blank boundaries for notice extraction so unrelated rows are not joined across a discarded separator. Keep joined matched text and existing version/scope behavior. A limited `allOf` composition of existing prefix/glyph and containsAll matchers is sufficient; the existing `startsWith` primitive can express a literal glyph prefix without inventing a predicate family or a provider vocabulary set. Do not change generic status extraction or matcher semantics to implement this.
- A live quotation printed with a hard line break and the measured glyph leading the new logical row may match. So may a TUI repaint that recreates that same row shape. JSON or prose detection is not a generic parser here; no “all quoted tool output is rejected” promise survives that ambiguity. E4 requires rejection of **prefixed logical rows and their soft wraps**, not indistinguishable glyph-led logical-row quotations. Criterion 7 documents the latter residual, rather than excusing the former false positive.

This replaces the initial “complete refusal block” proposal. The recorded incident fragment contains the actual glyph, so glyph presence alone is insufficient; the retained prefix is the measurable reason the bounded anchor rejects it. Requiring every suffix of an entire sentence would be a different matcher expansion and is not proposed.

### Handoff representation and explicit version-skew limits

Handoff keeps the SAME PTY; new spawn with SeedSnapshot does not. `SessionHandle::handoff_parts` currently snapshots the primary under the state lock; `handoff.rs` carries it in `HandoffSession.snapshot` after quiescing readers; `startup.rs:288-343` restores it for display and recovery. None of those existing fields identifies which primary cells came from a seed.

| Representation | Assessment |
| --- | --- |
| Reuse `HandoffSession.snapshot` for projection | Loses primary display/history state; violates the existing snapshot consumer contract. |
| Derive live projection from that primary snapshot | Impossible to separate indistinguishable seeded/current cells at this point; only a compatibility fallback with the limitation below. |
| Hide a second VT payload or origin metadata in `TerminalSnapshot.vt`, version, cursor or sequence | Overloads display/restore fields consumed outside handoff and widens the contract. Reject. |
| Add projection content to general TerminalSnapshot/recovery/SeedSnapshot | Reaches more producers and consumers than handoff needs. Reject for this bounded task. |
| Transfer raw PTY bytes or restart empty | Existing representation has no replay of all already-consumed bytes; adding one is larger, while empty drops an already-painted pending refusal. |
| Add `notice_snapshot: Option<TerminalSnapshot>` to HandoffSession | Selected refinement: reuse the existing snapshot representation as the value of one distinct optional field. Preserve the primary snapshot unchanged. No new command/event, protocol-version negotiation, fd, trust rule or lifecycle owner. |

The additive field is serialized/deserialized with default None and omitted when absent. Capture it under the same state lock and existing quiesced transfer boundary as the primary; restore it only for same-PTY adoption. Fresh SeedSnapshot never fills it. `Some(empty snapshot)` is a valid current projection before first output and must not be confused with None. Do not transfer `published_notice`; server idempotence already owns duplicate recovery. No server production change is needed.

The architect's selected fallback is retained explicitly as a compatibility exception: when the optional projection is absent/unusable (older v2 OR older v3 sender, projection serialization/restore failure, degraded transfer), seed the notice projection from the primary snapshot if usable and log the fallback. If neither snapshot is usable, start empty and log the loss. This chooses possible old false positives over silently suppressing all already-painted genuine refusals that remain recoverable from a primary snapshot.

Accordingly, revise E7 and invariants I1/I5 rather than claiming a universal guarantee:

- Fresh PTY and uninterrupted successful transfers of its live-only projection: exclude seeded content, preserve recoverable genuine pending notice evidence and displayed history. These are the strong provenance controls.
- Missing/unusable projection with a usable primary: display remains preserved; a measured pending refusal can be recovered, but primary seed content may also announce a notice. This is the known compatibility behavior, not a passing no-false-notice case. A projected snapshot from a session that already took this fallback can carry that ambiguity through further current-to-current handoffs. “The immediate sender is current” or “the field is present” is therefore not proof of a clean origin. Keep this lineage limitation explicit; do not add a wire provenance flag or recovery policy to imply otherwise.
- Neither snapshot usable: the already-painted refusal cannot be reconstructed; future genuine output remains eligible. It is not truthful to promise preservation of unavailable evidence. Missing CLI version separately keeps existing version-bounded notice suppression; never invent a version to make a legacy control pass.
- Current-to-older transfer: an older receiver ignores the optional field and retains its previous behavior. A subsequent return to a new receiver follows the same compatibility exception. No trust handshake/version bump is proposed to forbid this path.
- Re-announcement after adoption is permitted; exactly one automatic recovery belongs to the existing idempotent server record for the same run/provider/scope. Tests must distinguish one notice per uninterrupted session latch from at most one consumer recovery across handoff.

This is the smallest reviewed representation that preserves both terminal projections without changing display serialization or trust protocol. It does not solve historical provenance that an older/degraded sender never retained. Production remains held for manager acceptance of these explicitly narrowed terms.
