The software factory: a pipeline's definition, a run on the Desk, and runs compared

A pipeline is a small text file in the repo (.kanna/pipelines/feature.kojo) that says which stages a change goes through: an agent session, a command, a question for you, or a merge, joined by arrows with gates and bounded loops. The spec and mockup are made and approved in the task's chat first, as always; then its agent runs the pipeline (kanna run start feature): the task looks as it always does, its agent on the left and tabs on the right, and the pipeline builds under the hood in workers, agent sessions and commands in hidden terminals, driven by the daemon. The Run tab draws where it is; a watch tab shows the current stage's agent at work. A run is one task wherever tasks show. Every stage's time, turns, tokens, verdicts and your interventions are kept, so pipelines can be compared on the Stats tab and tuned.
