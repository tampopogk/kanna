Merge queue: “merge” hands the branch over, and main moves only to what was tested

You tell a ready task's agent to merge. It runs kanna task merge: its agent quits, its tabs close, and the task leaves the Desk for the repo's merge queue, shown in the Desk view between the Desk and the Shelf. The queue runs one entry at a time: the branch merged onto main as it is now, in a worker, the repo's tests run there, then main fast-forwards to that merge, and the next entry is merged on top of it. A merged entry leaves the queue and its task is Done. One whose tests fail goes back to the Shelf, red, and its agent gets the log.
