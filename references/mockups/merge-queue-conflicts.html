Merge queue: a branch that conflicts with main is taken, and the queue's pipeline resolves it

kanna task merge queues a branch without checking it against main. When its turn comes, the pipeline's first stage merges it onto main in the queue's worktree. A clean merge goes straight to the tests. A conflict leaves the worktree mid-merge and goes to the resolver, an agent that resolves only the conflicted files, keeping both sides' intent, and commits the merge; the tests and the judge then run on its resolution. A resolver that isn't sure fails, and the task goes back to the Shelf with what it found. The entry shows resolving beside testing and judging.
